# Physical validation: POCO Pad X1

Run date: 2026-10-27. This report summarizes one physical run; it is not a device compatibility promise.

## Test identity and conditions

- Device: POCO Pad X1; inventory model `Xiaomi 25099RP08G`, Android 15 / API 35, arm64-v8a.
- Firmware: HyperOS `OS2.0.205.0.VOZMIXM` (`POCO/uke_p_global/uke:15/AQ3A.240801.002/OS2.0.205.0.VOZMIXM:user/release-keys`).
- Build: current development source, commit `d9c375993eb0e4be78f1fa2868ca497ce345bb14`, source-tree SHA-256 `46d4e87dc6e2a7a88cfb5f6f0f81f9f7636df592c33817bcbf1cb768917772dc`; DPC reported `0.1.0-dev`, APK version 1.
- Transport: HTTP over LAN IP `192.168.101.5`; internet remained available. The router could not block WAN while preserving LAN.
- One managed identity, Device Owner reported true. The device ID, token, signing key, database and full logs remain in the private run directory.

## Results

| Status | Observed behavior |
| --- | --- |
| PASS | Factory-reset QR setup completed online; the server recorded one `MANAGED` Device Owner and authenticated sync. This does not qualify offline setup. |
| PASS | Signed configuration app v1 installed and v2 updated with the expected signer. A duplicate idempotency key returned the original operation; reusing it with a different APK was rejected. A requested downgrade was rejected and inventory retained v2. The server observed success for install/update; the user opened the app manually. The local Operations view did not retain the rejected downgrade attempt. |
| PASS | The independent app applied configuration, updated its title/button state and returned to defaults after policy release. Values survived app force-stop/reopen and an offline device reboot. |
| PASS | Authenticated background sync was observed after overnight idle and again after an approximately 30-minute idle period. Server timestamps advanced for the same identity. Process liveness was not monitored continuously. |
| PASS | Same-data server restart retained identity and operation state. During LAN loss, the app kept its cached configuration and a new revision stayed pending; a manual “Sync now” after reconnect applied it. After a separate offline reboot, the configuration remained available and Kylok synced after Wi-Fi returned without being opened. Automatic reconnect timing after ordinary LAN loss was not isolated. |
| PASS | Camera blocking/restoration, screenshot blocking/restoration, account modification restriction/restoration, and debugging restriction were observed. The debugging restriction hid Developer options; after release the user had to tap Build number seven times to show them again. USB debugging remained off. Screen recording was not tested. |
| FAIL | Android allowed the configuration app to be uninstalled while `no_uninstall_apps` was reported `APPLIED`. The required app later returned as signed v2 before manual sync; the recovery trigger was not isolated. Do not claim uninstall prevention works on this firmware. |
| BLOCKED | WAN-offline provisioning: router could not isolate WAN. Secure lock timeout: the tablet had no PIN/password/pattern. Add-user enforcement: no Add user action was available; the multi-user switch stayed enabled. Kylok process interruption: Android blocked Force stop and no ADB device was connected. |
| NOT RUN | Kiosk, runtime permission fixtures, DPC self-update, download/callback fault injection, API 37, alternate domain/TLS origins, revocation and other firmware/models. |

The test app remains installed as v2, the managed device identity is unchanged, and empty policy revision 24 is acknowledged. See the [physical test runbook](../physical-device-tests.md) for remaining procedures.
