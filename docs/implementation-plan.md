# Implementation plan

This plan describes current source contracts and remaining work. N1–N4 are implemented; N5–N7 are planned. The POCO Pad X1 run confirmed the independent configuration app receives, applies and releases configuration. Physical `HostOptions` coverage remains open, and Android allowed uninstall despite the reported restriction. See [physical evidence](validation/2026-10-27-poco-pad-x1.md). SDK contracts are documented in [SDK integration](sdk.md).

## Neutral integration boundary

A host handler authenticates its caller and maps transport DTOs into application commands. Its application service resolves an authorized scope, validates business policy and invokes a small consumer-owned port implemented by a Kylok adapter. Bootstrap constructs one SDK, mounts its agent handler and owns shutdown. Do not import a host framework, authorization engine, database wrapper or business model into either SDK.

Keep a host-owned mapping from `(scope ID, Kylok device ID)` to external entities. An enrollment correlation is an opaque association hint, never authorization or an authentication credential. Validate both scope and entity ownership before persisting a mapping. Empty/all-tenant filters from a host must be resolved explicitly into authorized Kylok scopes; an empty scope never means global access.

A host database commit and an SDK operation are separate durable actions. Use a host outbox/intent and stable idempotency key, then project authoritative SDK reads/change records back into host state. Specify recovery for either ordering; do not promise one transaction across providers or rely on callbacks for audit delivery. A retained change feed supports projection recovery, not permanent audit storage; hosts must export records they need to retain. A transactional custom provider can implement stronger integration only through a documented contract.

Artifacts remain immutable and digest-addressed through `ArtifactStore`. An object-store adapter may implement the existing contract; direct redirects/presigned URLs require a separate authorization design before inclusion. Host policy validation runs before SDK submission; it cannot bypass platform capability or SDK checks.

Android command/configuration work must follow the current [DevicePolicyManager contract](https://developer.android.com/reference/android/app/admin/DevicePolicyManager). In particular, DPC configuration readback and an application's own acknowledgement are separate observations; reboot/lock methods need platform-specific outcome rules.

## Working rules

Keep public usage examples, provider conformance, failure tests, generated API documentation and both site languages aligned with current APIs. Update the roadmap when each planned exit condition has evidence. The [testing strategy](testing.md) maps current checks and future suites; physical qualification can proceed independently of new feature work.
